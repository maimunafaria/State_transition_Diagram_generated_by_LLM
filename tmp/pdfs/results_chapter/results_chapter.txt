1. Introduction 
This chapter presents and analyses the empirical results of the study on generating UML state transition 
diagrams from natural-language requirements using open-source large language models (LLMs). The 
evaluation covers the effects of prompting strategies, retrieval-augmented generation (RAG), automated 
syntactic and structural validation, iterative repair, semantic graph-overlap metrics, generation stability, and 
LLM-as-a-Judge evaluation. The chapter first reports the original generation and repair findings, then presents 
the extension comparing baseline repair with syntax-grounded repair and examining the alignment of three 
LLM judges with human evaluators. 
The analysis is organised around three complementary notions of quality. First, syntactic validity determines 
whether the generated PlantUML code can be parsed. Second, structural validity checks graph-level UML 
constraints, including lifecycle, reachability, duplicate transitions, and special-node rules. Third, semantic 
quality examines whether the diagram represents the intended behaviour through State F1, human judgment, 
and LLM-based judgment. This separation is necessary because a diagram can compile successfully and 
satisfy structural rules while still omitting or contradicting required behaviour. 
2. Experimental Setup 
2.1 Dataset and Split 
The benchmark contains 80 requirement–diagram pairs collected from software-engineering textbooks and 
UML instructional materials. Each item includes a structured natural-language requirement and a 
corresponding ground-truth PlantUML state transition diagram. Twenty-seven cases were selected as the 
held-out test set, while the remaining 53 cases were used only for prompting examples and retrieval support. 
The test cases were excluded from the example pool and the RAG corpus to reduce information leakage. 
The dataset covers simple, medium, and complex diagrams. Complexity was operationalised using the number 
of states: simple diagrams contain at most six states, medium diagrams contain seven to fourteen states, and 
complex diagrams contain more than fourteen states. These thresholds correspond to the 25th and 75th 
percentiles of the dataset distribution.

2.3 Validation and Repair 
Every generated output was checked using the PlantUML command-line validator and a deterministic 
rule-based graph analyser. The structural analyser verifies exactly one initial transition, at least one final 
transition, absence of duplicate transitions, reachability, absence of orphan states, valid choice/fork/join 
behaviour, valid use of history states, and reliable graph extraction. 
The original study used a validation-aware repair workflow in which detected syntax and structural violations 
were supplied to the same LLM that generated the diagram. The extension compares this baseline repair 
prompt with a syntax-grounded repair prompt that provides targeted guidance relevant to the detected 
violation. Both repair methods were applied to the same set of 108 cases, enabling paired comparison. 
2.4 Human and LLM Evaluation 
Only diagrams that passed both syntactic and structural validation were submitted for semantic quality 
evaluation. Human evaluators rated four criteria on a five-point Likert scale: completeness, correctness, 
understandability, and terminological alignment. Scores below five required a short justification. 
Three LLM judges evaluated the same requirement–diagram pairs using the same rubric content. DeepSeek 
and Llama evaluated all four criteria in one structured JSON response. Prometheus evaluated one criterion per 
call using its rubric-based absolute-grading format. The LLM judges were not used as formal syntax or 
structural validators; their role was to approximate human semantic assessment after automated filtering. 
2.5 Computing Environment and Hyperparameters 
CPU, GPU/VRAM, RAM, operating system, Python version, Java version, PlantUML version, Ollama 
version, exact model tags/digests, quantisation, temperature, top-p, context length, maximum output 
tokens, and embedding-model version. State explicitly that all experiments were inference-only and no 
model fine-tuning was performed. 
3. Evaluation Metrics 
3.1 Syntactic and Structural Validity 
Syntactic validity is a binary measure indicating whether PlantUML accepts the diagram without an error. 
Structural validity is also binary and is satisfied only when all deterministic graph rules pass. These metrics are 
reported as the percentage of outputs that pass each stage. 
3.2 State, Transition, and Overall F1 
State matching uses semantic one-to-one alignment between generated and ground-truth state labels. Initial, 
final, choice, fork, join, and history pseudostates are excluded. Candidate and reference states are embedded 
locally, pairwise cosine similarities are calculated, and the Hungarian algorithm selects a maximum-weight 
one-to-one alignment subject to a configurable similarity threshold. 
Precision = TP / (TP + FP)     Recall = TP / (TP + FN)     F1 = 2PR / (P + R) 
Transition matching is topology-based after semantic state alignment. A generated transition matches a 
reference transition when its mapped source and target states are the same. Transition labels are optional and 
are retained as diagnostic information rather than required for the primary topology match. Overall F1 is the 
macro-average of State F1 and Transition F1. 
Overall F1 = (State F1 + Transition F1) / 2

3.3 Repair Metrics 
Strict repair validity is the proportion of repaired diagrams that pass both syntax and structural checks. 
Error-resolution rate is the number of initially detected violations that are removed divided by the total number 
of initial violations. These two metrics are complementary: a repair may resolve one violation yet remain 
invalid because another violation persists, or a new violation is introduced. 
3.4 Stability 
Stability measures the consistency of a model across three independent runs of the same configuration. For 
each LLM, the mean State F1, Transition F1, Overall F1, syntax-validity rate, and structural-validity rate are 
first calculated separately for each run. The standard deviation of the three run-level means is then reported. 
Lower standard deviation indicates greater model-level stability. Mean case-wise standard deviation is 
additionally reported to avoid masking offsetting changes across cases. 
3.5 Human–LLM Agreement 
LLM judge scores are compared with final human scores using Spearman rank correlation, mean absolute error 
(MAE), exact agreement, within-one-point agreement, weighted Cohen’s kappa, and mean signed error. Mean 
signed error is calculated as judge score minus human score; negative values therefore indicate systematic 
under-scoring.

5. Comparative Analysis 
5.1 Prompting, Retrieval, and Repair 
The results establish a clear hierarchy of workflow effects. Examples are highly effective for syntax 
acquisition, but they are insufficient for preserving global lifecycle properties. RAG does not provide a 
uniform advantage; its value depends on both the model and the retrieved source. Repair has the strongest 
effect on structural validity because it supplies precise feedback after generation rather than relying only on 
context provided before generation. 
The syntax-grounded extension improves the resolution of difficult, rule-specific violations, but it does not 
dominate the baseline for every error type. This argues against a single universal repair prompt. A practical 
system should select targeted guidance based on the detected violation while retaining simpler repair 
instructions for local errors that general LLMs already handle well. 
5.2 Automated Metrics versus Human Quality 
Automated syntax and structural checks are necessary but not sufficient. The original human evaluation 
showed that understandability could receive a median score of five even when correctness was lower. 
Consequently, visually clear and structurally valid diagrams can still omit required flows or introduce 
unsupported behaviour. State and Transition F1 provide additional reference-based evidence, while human 
evaluation remains necessary for semantic and practical judgment. 
5.3 LLM Judges versus Human Evaluators 
None of the three LLM judges achieved strong enough alignment to replace human evaluation. DeepSeek was 
the most balanced overall, but its rank correlation and kappa remained weak. Llama showed slightly better 
rank correlation while under-scoring by approximately one point on average. Prometheus, despite specialised 
evaluation training, did not consistently outperform general-purpose models. The judges may therefore be 
useful for supplementary screening, prioritising cases for review, or generating initial critiques, but not as an 
independent ground truth for UML diagram quality. 
6. Statistical Analysis 
The experimental design supports paired non-parametric testing because the same requirements are evaluated 
under multiple strategies and the score distributions are bounded. Strict-validity differences between baseline 
and syntax-grounded repair should be tested using McNemar’s test on the paired case-level outcomes. Paired 
State F1, Transition F1, and Overall F1 should be compared using the Wilcoxon signed-rank test. When more 
than two generation strategies are compared, the Friedman test followed by Holm-corrected pairwise Wilcoxon 
tests is appropriate.

8. Discussion of Findings 
8.1 Why Examples Improve Syntax More Than Structure 
PlantUML surface syntax is local and highly imitable: examples expose keywords, arrow notation, state 
declarations, and diagram boundaries. Structural correctness is global. It requires reasoning across the 
complete lifecycle, checking whether all states are reachable, ensuring branching constructs are well formed, 
and preserving a consistent initial-to-final path. These properties are not guaranteed by reproducing the 
appearance of an example. 
8.2 Why Targeted Repair Helps Selectively 
Syntax-grounded repair is most beneficial when the violation corresponds to a precise, reusable structural 
pattern. The gains for orphan states, missing guards, and multiple initial transitions support this explanation. 
For straightforward edits such as adding a final transition or removing a duplicate, additional grounding may 
distract the model or encourage unnecessary changes, which explains why the baseline remained competitive 
or better for several local violations. 
8.3 Why LLM Judges Under-Score Humans 
All judges produced negative mean signed error. One plausible explanation is that the judge prompts explicitly 
enumerate every possible source of deficiency, encouraging strict criterion-by-criterion checking, whereas 
human evaluators may apply a more holistic interpretation and tolerate semantically equivalent abstractions. 
Prometheus evaluates one criterion in isolation, which may further intensify local fault detection. The result 
demonstrates that rubric equivalence does not guarantee identical scoring behaviour across human and 
machine evaluators.

8.4 Practical Implications 
●​ Use few-shot examples to obtain reliable PlantUML syntax, but do not treat successful compilation as 
evidence of correct behaviour. 
●​ Apply deterministic validation and targeted repair before semantic assessment. 
●​ Select repair guidance by violation type rather than relying on one universal prompt. 
●​ Retain human review for completeness and correctness, particularly in safety-critical systems. 
●​ Use LLM judges as supplementary reviewers or triage tools, not as replacements for expert judgment. 
9. Threats to Validity and Limitations 
9.1 Construct Validity 
Semantic State F1 depends on an embedding model, a similarity threshold, and one-to-one alignment 
decisions. Equivalent states may be missed, while similarly worded but behaviourally distinct states may be 
matched. Transition F1 intentionally treats labels as optional, which measures topology but may overestimate 
behavioural equivalence when two transitions connect the same states for different reasons. These risks should 
be mitigated through manual inspection of a representative sample and transparent release of all mappings. 
9.2 Internal Validity 
LLM outputs depend on prompt wording, inference parameters, quantisation, and nondeterministic decoding. 
The stability study addresses some of this variability, but only three repeated runs are available. Repair results 
may also depend on the exact violation message supplied to the model. The comparison of LLM judges uses 
different calling structures for Prometheus and the general-purpose models, so observed differences reflect 
both model capability and prompt interface. 
9.3 External Validity 
The benchmark is derived primarily from textbook examples and may not represent the ambiguity, scale, 
hierarchy, concurrency, and timing constraints of industrial systems. The test set contains 27 requirements, and 
all evaluated generators are open-weight models of moderate size. Generalisation to proprietary models, larger 
models, industrial requirements, and other UML diagram types therefore requires further study. 
9.4 Human and LLM Evaluation 
Human evaluation is subjective and was conducted only on diagrams that passed automated validation. 
Consequently, the LLM-as-a-Judge results apply to the semantic assessment of already-valid diagrams and 
cannot establish whether LLM judges detect syntax or structural invalidity. Prometheus produced fewer valid 
criterion rows than DeepSeek and Llama, creating unequal sample sizes. Headline judge comparisons should 
therefore be confirmed on a common complete-case subset. 
9.5 Potential Same-Model Confounding 
DeepSeek and Llama aligned more closely with humans on outputs produced by their own model families. 
However, this apparent advantage is confounded by unequal sample sizes and differences in strategy and 
diagram difficulty. It should be reported as a same-model pattern rather than definitive self-evaluation bias 
unless a controlled analysis confirms the effect.

10. Summary 
The results show that reliable state transition diagram generation requires a layered workflow. Prompt 
examples sharply improve syntactic validity, but initial structural validity remains low. RAG is model- and 
source-dependent and may introduce behaviour from mismatched examples. Automated repair provides the 
largest structural gains, with DeepSeek performing particularly strongly in the original workflow. The 
syntax-grounded extension resolves more individual violations and improves full-diagram validity modestly, 
but its advantage varies by violation type. 
Human evaluation confirms that structurally valid diagrams can still be behaviourally incomplete or incorrect. 
LLM judges only weakly reproduce human scores: DeepSeek provides the best overall balance, Llama shows 
the highest rank correlation but the strongest under-scoring, and Prometheus does not consistently outperform 
the general-purpose judges. The combined evidence supports using automated validators, targeted repair, 
semantic graph metrics, and LLM-based critique as complementary aids while retaining human assessment as 
the final authority for behavioural quality.
