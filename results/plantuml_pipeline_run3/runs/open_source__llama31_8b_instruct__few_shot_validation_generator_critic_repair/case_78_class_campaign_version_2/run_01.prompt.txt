Example 2 Requirement:

Functional Requirements
1. The system shall check if the entered PIN is correct.
2. The system shall ask for the PIN again if it is incorrect.

4. The system shall return the card if the user cancels the process at any moment during this stage.
5. The system shall display options for the user to choose from if the PIN is correct.
6. The system shall process the withdrawal request and check if it can approve the transaction.
7. The system shall cancel everything and return the card if the withdrawal request is rejected.
8. The system shall dispense cash, print a receipt, and return the card if the withdrawal request is approved.
9. The system shall stop the operation if it runs out of cash during the process.
10. The system shall reset itself to be ready for the next user after completing or ending the session.

6. The system shall allow doctors to view shared information from quarantined users and suggest medicines.
7. The system shall enable users to view a list of nearby medical shops and purchase medicines online.
8. The system shall allow assigning workers to clean an area, updating the cleanliness status accordingly.

--- Process ---

1. Identify all system states.

2. Identify events/conditions triggering transitions.

3. Define transitions clearly between states.

4. Ensure logical consistency (no unreachable states).

5. Identify one initial state and at least one final state.



--- Output Rules ---

- Generate ONLY valid PlantUML code.

- Include initial and final states.

- Use proper UML state diagram syntax.

- Do not include explanations or extra text.

8. The system shall handle payment after the campaign completion and generate a refund if the amount paid is less than required.
9. The system shall wait for the correct balance to be settled if the amount paid exceeds the required amount.
10. The system shall mark the campaign as paid once the full amount is properly paid.
11. The system shall archive the campaign and release all assigned staff and managers.
