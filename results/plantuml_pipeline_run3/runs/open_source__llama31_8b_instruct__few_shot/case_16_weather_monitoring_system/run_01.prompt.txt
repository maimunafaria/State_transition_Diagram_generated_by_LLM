--- Process ---

1. Identify all system states.

2. Identify events/conditions triggering transitions.

3. Define transitions clearly between states.

4. Ensure logical consistency (no unreachable states).

5. Identify one initial state and at least one final state.



--- Output Rules ---

- Generate ONLY valid PlantUML code.

- Include initial and final states.

- Use proper UML state diagram syntax.

- Do not include explanations or extra text.

Weather Monitoring System — Polished Requirement Specification

Functional Requirements
1. The system shall allow a user to create an account.
2. The system shall allow a user to log in to their existing account.
3. The system shall end the process if the registration is not successful.
4. The system shall allow a user to check the weather for their current location or another location after logging in.
5. The system shall end the process if a new location entered is not valid.
6. The system shall allow a user to choose what to check (temperature, humidity, rainfall, pressure, or dew point) if the entered location is valid.
7. The system shall update and show the selected weather information to the user.
8. The system shall allow a user to view additional weather details (alerts, a weekly analysis, a future prediction, or a graph).
9. The system shall end the session when the user logs out.
