Requirement:
Class Campaign Version 2 — Polished Requirement Specification

Functional Requirements
1. The system shall start a campaign after a manager and staff are assigned.
2. The system shall activate the campaign once everything is approved and the contract is signed.
3. The system shall prepare adverts during the campaign.
4. The system shall approve and schedule the adverts.
5. The system shall run the adverts.
6. The system shall allow extension or adjustment of the campaign while it is running.
7. The system shall complete the campaign and prepare a final statement after all adverts have finished.
8. The system shall handle payment after the campaign completion and generate a refund if the amount paid is less than required.
9. The system shall wait for the correct balance to be settled if the amount paid exceeds the required amount.
10. The system shall mark the campaign as paid once the full amount is properly paid.
11. The system shall archive the campaign and release all assigned staff and managers.

**States:**

* Assigned (manager and staff are assigned)
* Approved (everything is approved and contract is signed)

* Paused (campaign is paused for extension or adjustment)
* Completed (all adverts have finished)

**Initial state:**

* Unassigned (no manager and staff are assigned)

**Final states:**

* Paid (full amount is properly paid)
* Archived (campaign is archived and all assigned staff and managers are released)

**Events or conditions:**

* Manager and staff assignment
* Approval of everything and contract signing
* Advert preparation and scheduling completion
* Campaign extension or adjustment request
* All adverts finishing
* Payment made
* Correct balance settlement

**Transitions:**

1. Unassigned → Assigned (manager and staff are assigned)
2. Assigned → Approved (everything is approved and contract is signed)
3. Approved → Running (campaign starts, adverts are prepared and scheduled)
4. Running → Paused (campaign is paused for extension or adjustment)
5. Paused → Running (campaign resumes after extension or adjustment)
6. Running → Completed (all adverts have finished)
7. Completed → Paid (full amount is properly paid)
8. Completed → Archived (campaign is archived and all assigned staff and managers are released)

**Missing or ambiguous details:**

* What happens if the manager and staff are unassigned while the campaign is running?
* How does the system handle payment for a campaign that has already been completed?

You are a UML modeling expert.

Example requirement:
Telephone — Polished Requirement Specification

Functional Requirements
1. The system shall provide a dial tone upon receiver pickup.
2. The system shall start processing the entered number when the user begins entering digits.
3. The system shall inform the user or play a message if the entered number is incomplete or incorrect.
4. The system shall play a message to prompt the user if they stop dialing for a while.
5. The system shall attempt to connect the call once a valid number is entered.
6. The system shall play a busy tone if the line is busy.
7. The system shall start ringing on the other end if the connection goes through.
8. The system shall connect the call and allow both parties to talk when the person being called answers.
9. The system shall end the call and return to an idle state if either party hangs up.
10. The system shall allow calls to be stopped or terminated at any point.

Example PlantUML:
@startuml
title Telephone State Machine

[*] --> Idle

Idle --> Active : lift receiver / get dial tone
Active --> Idle : caller hangs up / disconnect

state Active {

    [*] --> DialTone

    state DialTone
    DialTone : do / play dial tone

    DialTone --> Dialing : dial digit(n)
    DialTone --> TimeOut : after (15 sec.)

    state Dialing

    Dialing --> Dialing : dial digit(n) [incomplete]
    Dialing --> Connecting : dial digit(n) [valid] / connect
    Dialing --> Invalid : dial digit(n) [invalid]
    Dialing --> TimeOut : after (15 sec.)

    state Invalid
    Invalid : do / play message

    state TimeOut
    TimeOut : do / play message

    state Connecting
    Connecting --> Busy : busy
    Connecting --> Ringing : connected

    state Busy
    Busy : do / play busy tone

    state Ringing
    Ringing : do / play ringing tone

    Ringing --> Talking : callee answers / enable speech

    state Talking
    Talking --> Pinned : callee hangs up
    Talking --> Pinned : callee answers

    state Pinned

}

Active --> [*] : terminate
Active --> [*] : abort

@enduml
